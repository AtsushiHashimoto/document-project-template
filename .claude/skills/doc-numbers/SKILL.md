# Doc Numbers — 数値監査

`.claude/rules/template/numbers.md` を正典とする。**本スキルは検査の定義を再定義しない。**
必ず正典を読んでから始める。モデル指定はない。

## 手順

### Step 0: 前提の読み込み

1. `.claude/rules/template/numbers.md`（検査の正典）
2. 対象ファイル（引数指定。無指定なら本文の主ファイル）
3. `docs/surveys/` の一覧（検査aの照合先）

### Step 1: 数値台帳の作成

対象ファイルから数値を含む行を機械的に抽出し（grep）、台帳に落とす。
金額・年・期間・人数・割合・件数・条文番号・構造の数（〜点、〜型、〜層）を漏らさない。
コメント・TODO内の数値は台帳に含めるが「提出物外」と区別する。

### Step 2: 検査a〜d

正典の定義どおりに実行する。とくに:

- **検査aの照合は必ず `docs/surveys/` のファイルに対して行う。**
  記憶と一致しても記録に無ければ「検証不能」
- 検査cは計算を実際に行う（暗算で済まさず、必要なら計算する）
- 検査dの出力は橋渡し文の提案であり、数を変えない

### Step 3: 報告

1. **台帳**（検証済みの対は ✓ を付けて全数掲載。何を確認したかが後から追えるように）
2. **所見**を重大度順に:
   算術の誤り・出典との不一致 ＞ 文書内の食い違い ＞ 検証不能 ＞ 見かけの矛盾
3. 修正提案は diff 形式。**ファイルは変更しない**（点検と書き換えを分ける）
4. 「検証不能」は誤りと書かず、`/doc-survey` への作業項目として列挙する
5. 所見ゼロの検査も「所見なし」と明示する

## 禁止事項

- 記憶を照合先として「確認済み」と報告すること
- 数値そのものを変える提案（検査dは橋渡し文のみ）
- 出所の規律（プロジェクトの定めがある場合）を破る数値の加筆提案
