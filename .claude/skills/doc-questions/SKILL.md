# Doc Questions — 質問票の生成

**文書は質問への回答の集まりである。** 全体を考えると途方に暮れるが、
各質問に分割すれば1問ずつ片づけられる。

この方法は慶應義塾大学 杉浦孔明研究室の「60 Questions & Answers」に着想を得ている
（国際会議論文は約60段落からなり、60個の質問に答えれば論文が完成する、という考え方）。

**借りたのは「質問票という装置」であって、60QAの質問項目そのものではない。**
60QAの質問リストと記入順序は国際会議論文に最適化されており、
申請書・提案書・報告書にそのまま当てはめてはならない。
本スキルは、装置だけを取り出し、**質問票を文書ごとに一次資料と二次資料から生成する**形に
一般化したものである。

## 前提

`worksheet/constraints.md` と `worksheet/criteria.md` が揃っていること。
二次資料があれば `docs/references/` も読む。無ければ先に `/doc-init`。

## Step 0: ★ 既製の質問票があるか確認する

**ゼロから生成する前に、必ず確認する。**

1. `docs/question-sets/` に**過去の自分の質問票**が無いか（前回の副産物）
2. ユーザーが**指導教員・研究室・学会から受け取った質問票**を持っていないか
   （60QAのように、そのまま使える形で流通しているものがある）
3. `docs/references/` の二次資料に質問リスト形式のものが無いか

既製のものがあれば**それを土台にする。** 実績のある質問票は、
一次資料からは読み取れない「評価者が実際に気にすること」を含んでいる。

その場合の作業は生成ではなく**突き合わせ**になる。

- 既製の質問 → この文書の形式項目・評定要素のどれに対応するかを注記する
- **対応先の無い質問**は、この文書には不要かもしれない。ただし削除は慎重に。
  一次資料に現れない観点こそ二次資料の価値である
- **どの質問にも対応されない評定要素**を洗い出し、質問を追加する。ここが最も重要

## Step 1: 質問の供給源を並べる

質問は3つの源から作る。**それぞれ由来を記録する。**

| 由来 | 何から作るか | 例 |
|------|------------|-----|
| **形式** | 様式が定める記載項目 `(1)(2)(3)…` | 「本研究の着想に至った経緯は何か」 |
| **評価** | 評定要素の一行ずつ | 「より広い学術・社会への波及効果は何か」 |
| **作法** | 二次資料が「書くべき」とする要素 | 「国際競争性における自分の優位性は何か」 |

**評定要素は必ず1つ以上の質問に対応させる。** 対応する質問が無い評定要素は、
そのまま記述の欠落になる。

## Step 2: 質問を書く

- **質問の形にする。** 「〜について」ではなく「〜は何か」「なぜ〜か」
- 質問者は**評価者**を想定する。可能なら具体的な人物を思い浮かべる。
  「その人からメールが届いた」と考えると回答の粒度が決まる
- 1問 = 1段落。答えが2段落になる質問は分割する
- 各質問に注記する

| 注記 | 内容 |
|------|------|
| 由来 | 形式(N) / 評定要素ID / 二次資料名 |
| 状態 | ▲未着手 / ●トピックセンテンスのみ / ○確定 |
| 分量目安 | 行数または字数 |
| 依存 | 先に答えておくべき質問の番号 |

## Step 3: 記入順序を決める

**★ 導入は最後に書く（一般則）。**
文書の導入（はじめに・背景・概要・要旨）は、本体が確定してから書く。
これは論文に限らず、申請書・提案書・報告書・設計文書のいずれでも成り立つ。理由は3つある。

- 導入の仕事は**これから来るものを設定すること**である。来るものが決まる前に書けば必ず外れる
- 早く書いた導入は**錨になる**。本体が導入に合わせて歪む。
  結果に合わせてゴールを書き換えるのと同じ失敗である
- 導入は**最も書き直される部分**であり、早く書いた労力はほぼ捨てることになる

依存関係の少ない中核から埋め、外側を最後に回す。既定の順序:

```
1. 中核（何を問うのか、何をするのか）
2. 方法・計画
3. 位置づけ・独自性
4. 1〜3 を行き来して整合を取る
5. 結論・波及効果
6. 背景・導入                              ← ここで初めて着手
7. 概要・要旨                              ← 最後
```

各段は完了率が3分の2程度に達したら次へ進み、行き来しながら100%にする。
一段ずつ完璧に仕上げようとすると進まない。

**用語定義や前提が誤ったまま先に進むと、多数の回答に同じ誤りが伝播し、
結局まとめて手戻りになる。** これが順序を守る最大の理由である。

## Step 4: 質問票を調整する

生成した質問票は最大公約数的なので、この文書に合わないものが必ず混じる。
**通常は1〜2割をカスタマイズまたは削除する。**

削除する場合は**削除した理由を残す**。後から「なぜこの観点が無いのか」を
問われたときに答えられるようにするため。ただし、**評定要素由来の質問は削除しない。**
答えにくいという理由で削ると、そのまま失点になる。

## Step 5: 書き出し

`worksheet/questions.md` に保存する。冒頭に節ごとの完了率を置く。

```markdown
# 質問票

生成日: YYYY-MM-DD / 制約の版: <constraints.md の版>

| 節 | 完了 |
|----|------|
| 1. 背景と問い | 0/8 |
| 2. 目的と独自性 | 0/5 |
...

## 1. 背景と問い

### Q1 ▲ 本研究が対象とする領域で、誰もが同意する現状は何か
- 由来: 形式(1) / 評定要素 A(1)c
- 分量目安: 4行
- 依存: なし

（回答をここに書く。第1文はトピックセンテンス）
```

## Step 6: 次へ

質問票ができたら `/doc-outline` で**全問のトピックセンテンスだけ**を先に埋める。
いきなり本文を書かない。

## Step 7: 再利用資産として残す

**この文書のために磨いた質問票は、次回の最大の資産になる。**
文書が完成したら `/doc-harvest` で `docs/question-sets/<文書種別>.md` に書き出す。

質問票は使うたびに良くなる。とくに次の2つは一次資料からは決して得られない。

- 実際に答えてみて**答えにくかった質問**（＝質問の切り方が悪い）
- 書いてみて**必要だと分かった質問**（＝一次資料にも二次資料にも無かった観点）

## 回答のべからず

- 単語のみ、体言止め、「〜であるため。」で終わらせない。**常に文で答える**
- 第1文は必ずトピックセンテンスにする。前置きから始めない
- 質問に答えていない回答を書かない。「聞かれていることに答える」が基本
