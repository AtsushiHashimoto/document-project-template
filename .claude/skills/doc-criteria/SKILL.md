# Doc Criteria — 評価基準の採取

## 採取項目

- **評定要素を一行ずつ**表に落とす。要約も統合もしない。
  統合すると、統合された側の欠落が見えなくなる
- 各要素が**絶対評価か相対評価か**
- 各要素が**独立項目か、総合評点の一部か**
- 評価者の人数、評価の段数
- 「評価に考慮しない」と明記されている欄

## ★ 必ず確認する2点

**1. 評価者が「対応する記述が無い」ことを減点理由として選択できる仕組みか。**
そうであれば、記述の欠落は文章の巧拙と無関係に直接失点になる。
この場合、欠落の解消は認知負荷の改善より優先度が高い。

**2. 独立した絶対評価の項目があるか。**
総合評点とは別枠で評価される項目は、書かなければそのまま最低評価になる。
本文がどれだけ良くても救われない。**見落とすと最も損をする。**

## 読者像を書く

`worksheet/criteria.md` の末尾に評価者の想定を書く。

- 専門は近いか、遠いか
- 何本の文書を読むか（＝1本にかけられる時間）
- 分野の常識としてどこまで既知としてよいか

**この設定を誤ると直列化の全部が狂う。** 既知概念には記憶コストがかからないという
前提で新規概念を数えるため、読者像がずれると数え方がずれる。
既定は「専門は近いが同一ではない評価者」。

## 出力

`worksheet/criteria.md` を更新し、続けて `/doc-coverage` で対応表を再点検する。
