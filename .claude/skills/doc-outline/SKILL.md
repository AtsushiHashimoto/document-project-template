# Doc Outline — トピックセンテンス先行

**3節以上の文書では、いきなり本文を書かない。**
まず各段落のトピックセンテンスだけを書き出し、ユーザーとの対話で骨格を確定させる。

理由は2つある。本文まで書いてから骨格の誤りが見つかると、書いた文章が惜しくなって
**誤った骨格のまま辻褄を合わせにいく**。もう一つは、書き手の意図と
書かれた論理のずれは、修飾の多い本文よりトピックセンテンスの方がはるかに見つけやすい。

## 前提

- `.doc/questions.md` に質問票があること（無ければ `/doc-questions`）
- `.doc/graph.md` にマクロ直列化（概念の順序）があること（無ければ `/doc-graph`）

**グラフは概念の順序を決める。質問票は段落の枠を決める。アウトラインはその枠に
主張を1つずつ入れる。** それぞれ別の作業である。

## Step 1: 質問を段落に対応させる

質問票の各質問が1段落に対応する。`.doc/graph.md` の再直列化案と突き合わせ、
質問の並び順が概念の依存順と矛盾していないかを確認する。

- **1段落1主張。** 1つの質問への回答が2主張になるなら質問を分割する
- 新規概念を3個以上導入する段落は分割する
- 形式制約の項目境界をまたぐ段落を作らない

## Step 2: 全問のトピックセンテンスだけを書く

各質問について、**回答の第1文だけ**を書く。根拠も具体例も書かない。
**この段階では本文を1文字も書かない。**

記入順序は質問票の推奨順（中核から外側へ）に従う。背景と概要は最後。

満たすべき条件。

- **それ単独で意味が通る。** 「これについて述べる」「以下に示す」は主張ではない
- **反論可能である。** 誰も否定しない文（例:「本研究は重要である」）は主張ではない
- **段落の内容を予告している。** 読者がこの1文を受け入れたら、残りを飛ばせる

あわせて各段落に注記する。

| 注記 | 内容 |
|------|------|
| 導入 | この段落で初めて定義する概念 |
| 消費 | この段落で使う既出概念 |
| 破棄 | 読者がこの段落の後に忘れてよくなるもの |
| 評定要素 | `.doc/criteria.md` のどの要素に対応するか |
| 分量目安 | 行数または字数（この時点では粗くてよい） |

## Step 3: ★ 縦読み検査

**トピックセンテンスだけを順に読み、それだけで論旨が通るかを確認する。**
これが paragraph writing の中核であり、この検査を通らない文書は本文をどう磨いても通らない。

見るもの。

- 隣り合う2文の間に**飛躍**がないか。あれば段落が足りない
- 同じことを言っている2文がないか。あれば統合する
- **前方参照**がないか。まだ定義していない概念を含む主張が先に来ていないか
- 最後まで読んで、**文書の結論に到達しているか**

縦読みの結果を `.doc/outline.md` に書き出す。

## Step 4: ユーザーとの対話で深める

**ここでいったん止め、骨格をユーザーに提示する。** 本文には進まない。

提示するもの。

1. トピックセンテンスの一覧（縦読みできる形で）
2. 縦読み検査で見つかった飛躍・重複・前方参照
3. **判断を仰ぐ点**。とくに次の3つ

   - 主張の**強さ**（言い切るか、留保をつけるか）
   - 根拠として何を出すか（データ、先行研究、論理のみ）
   - **書き手しか知らない前提**が使われていないか

対話は段落単位で行う。「全部まとめて確認してください」は機能しない。
議論が必要な段落を3つ以内に絞って提示し、順に片づける。

**書き手の意図を推測で埋めない。** 埋めた箇所は必ず「ここは仮に置いた」と明示する。
とくに研究の設計上の前提（何を対象とし、何を対象としないか）を勝手に決めない。
ここでの取り違えは、本文を書いてからでは修正コストが跳ね上がる。

## Step 5: 確定と着手

トピックセンテンスが確定したら `.doc/questions.md` の各質問の状態を `●` にし、
`/doc-answer <質問番号>` で1問ずつ段落に展開する。

**確定後にトピックセンテンスを変えたくなったら、本文を書き足す前にここへ戻る。**
本文の都合で主張を変えるのは、結果に合わせてゴールを書き換えるのと同じ失敗である。

## 適用範囲

| 文書の規模 | 手順 |
|---|---|
| 3節以上 | **必須。** 全体のアウトラインを先に確定する |
| 1〜2節 | 任意。ただし段落数が5を超えるなら実施を推奨 |
| 1段落の修正 | 不要。`/doc-paragraph` から始めてよい |
