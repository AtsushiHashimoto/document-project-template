# Doc Survey — 文献サーベイ

**生成モデルは実在しない文献をもっともらしく書く。**
そのまま申請書や論文に載せると、査読者が引こうとした瞬間に信頼が消える。
本スキルは、その事故を手続きで防ぐ。

保存規約は
[research-project-template](https://github.com/AtsushiHashimoto/research-project-template)
の `deliverables.md` に従い、`docs/surveys/YYYY-MM-DD_topic-name.md` とする。

## ★ 検証プロトコル（厳守）

### 1. 陽性対照を毎バッチ置く

各バッチの先頭で、実在が確実な文献を取得して成功を確認する。

```sh
curl -L "http://export.arxiv.org/api/query?id_list=1706.03762"   # Attention Is All You Need
```

**失敗したら取得系の故障とみなし、そのバッチの結果を全部破棄して再試行する。**
陽性対照なしに「見つからなかった」と結論してはならない。

### 2. `curl -L` を省かない

`-L` がないと arXiv API が 301 を返し、**実在確実な文献まで NOT_FOUND になる**。
リダイレクト追従の欠落を「非実在」と読み違えるのが最も多い事故。

### 3. 非実在判定は2チャネル一致を必要条件とする

- **肯定は1チャネルで足りる**（見つかれば実在）
- **否定は2チャネル必要**。arXiv API と abs ページの**両方**が否定し、
  かつ陽性対照が成功した場合のみ「非実在」と判定する
- 片方だけの否定は **「検証不能」** に留める。断定しない

### 4. ID を差し替えない

取得に失敗しても ID を「近そうなもの」に変えない。
取得経路の切替は**同一 ID 内**（abs → html → pdf）に限る。

### 5. 逐語引用にはロケータを必ず付ける

`abstract` / `§n` / `Table n` / `vN` のいずれか。
**ロケータを書けない引用は載せない。**

### 6. 記憶で書かない

**存在を確認できていない文献は1本も載せない。**
1本も確認できなければ「確認できなかった」と正直に書く。
埋め合わせに「よく知られているように」と書き始めたら、それは創作である。

### 7. arXiv 以外の文献

古典（Weiser 1991 等）、規格（ISO/IEC）、学会論文は arXiv に無い。
DOI、出版社ページ、規格の公開概要ページで裏を取る。
**規格の全文は有料で読めないことが多い。その場合は「全文未確認」と明記する。**

## 証拠の格付け（5層）

arXiv の `comments` / `journal-ref` / `DOI` 欄で**機械的に**判定する。

| 層 | 定義 |
|----|------|
| ① | 査読誌・トップ会議採択（`journal-ref` または `DOI` 記入済） |
| ② | ワークショップ採択（`comments` に記載） |
| ③ | プロトコルのみ査読済（Registered Report） |
| ④ | 非標準の実験的会場 |
| ⑤ | **査読情報未確認** |

**⑤を「査読なし」と書いてはならない。** 欄が空であることは査読を経ていない証明にならない
（未記入・投稿中の可能性）。証拠のない断定は、本スキルが防ごうとしている誤りと同種である。

## 成果物の構成

`docs/surveys/YYYY-MM-DD_topic-name.md`

1. 見出し、**実施日**、対象 Issue（あれば）、**目的**
2. **結論を先に書く。** 何が分かったか。とくに
   **新規性が崩れる要素が見つかったかどうか**を最初に書く
3. 調査範囲と方法（検証プロトコル、**確認できた本数と確認できなかった本数**）
4. 証拠の格付け表
5. 各文献・各分類の内容（逐語引用にはロケータ）
6. **本申請（本論文）への適用メモ** — そのまま書ける形の位置づけ案。
   ここが無いと、ただの読書メモになる
7. **未解決・確認できなかったこと**

## 新規性が崩れたときの扱い

**崩れたら、それを最初に大きく書く。** 隠してはならない。
「既に解かれていた」と判明することはサーベイの成功であって失敗ではない。
後の段階で判明すると、それまでの作業が全部無駄になる。

`survey` を工程の先頭に置く理由がこれである。

## 2周目以降

**skip しない。** 内容は「ゼロからの調査」ではなく
「ここまでの結果を踏まえて追加サーベイが必要か」の検討になる。
不要と判断した場合も、skip ではなく**判断の記録を残して閉じる**。
結果が出るたびに探すべき場所が変わるため。

## 並列実行

テーマが複数あるときはサブエージェントで並列に走らせてよい。
その場合も**各エージェントに検証プロトコルを全文渡す**こと。
プロトコルを省略したエージェントは高い確率で実在しない文献を書く。
