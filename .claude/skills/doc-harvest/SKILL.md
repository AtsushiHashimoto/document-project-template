# Doc Harvest — 再利用資産の収穫

**今回のために磨いた質問票は、次回の最大の資産である。**
提出して終わりにすると、次回また一次資料から作り直すことになる。

## Step 1: 質問票を清書する

`worksheet/questions.md` から回答本文を落とし、**質問と注記だけ**を
`docs/question-sets/<文書種別>.md` に書き出す。

残すもの: 質問文、由来（形式項目／評定要素／二次資料）、分量目安、依存関係、記入順序。
落とすもの: 今回固有の回答内容、固有名詞、データ。

## Step 2: ★ 使ってみて分かったことを注記する

**ここが収穫の本体である。** 一次資料からは決して得られない情報を残す。

| 注記 | 内容 |
|------|------|
| 答えにくかった質問 | 質問の切り方が悪い。次回は分割するか言い換える |
| 追加した質問 | 一次資料にも二次資料にも無かったが必要だった観点 |
| 削除した質問 | なぜ不要だったか。**理由を残さないと次回また悩む** |
| 分量の実績 | 目安と実績のずれ。次回の見積りに使う |
| 順序の変更 | 既定の記入順序を変えた箇所とその理由 |

## Step 3: 制約と評価基準の版を記録する

質問票は**特定の版の様式と評価基準に紐づく**。版が変われば質問も変わる。

```markdown
対象: 科研費 基盤研究(B) 様式S-13
制約の版: 令和9(2027)年度公募
採取日: YYYY-MM-DD
次回の注意: 様式・評定要素の再採取から始めること。質問票の流用は突き合わせの後
```

**「前回と同じはず」で流用しない。** 次回はまず `/doc-constraints` `/doc-criteria` で
再採取し、`/doc-questions` の Step 0 で突き合わせる。

## Step 4: 結果が分かったら追記する

採否・査読結果が判明したら、`docs/question-sets/<文書種別>.md` の末尾に追記する。

- 結果と、開示された評点・コメント
- **どの評定要素が低かったか**。次回その質問を強化する
- 通った／落ちた理由の自己分析

**これが最も価値の高い情報であり、最も記録されない情報でもある。**
結果が出た時点では次の申請まで間があり、その頃には忘れている。
