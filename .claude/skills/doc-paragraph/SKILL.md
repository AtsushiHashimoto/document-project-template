# Doc Paragraph — ミクロ直列化

**いま書こうとしている段落・節の中だけ**を対象に、文レベルの順序を決める。
文書全体の骨格は扱わない。それは `/doc-graph` の仕事。

**段落を書く直前に毎回実行する。** 書いてから直すのではなく、書く前に順序を決める。

## 前提

`worksheet/graph.md` が存在し、この段落が全体のどこに位置づくかが決まっていること。
決まっていなければ先に `/doc-graph`。

## Step 1: この段落の役割を1文で書く

`worksheet/graph.md` を参照し、この段落が

- どの形式制約の項目に属するか
- どの評定要素に対応するか
- どの概念を**導入**し、どの概念を**消費**し、読者に何を**捨てさせる**か

を1文ずつ書き出す。ここが書けない段落は、書く必要がない段落である。

## Step 2: 段落内のノードを並べる

段落を構成する要素を分類する。

| 種別 | 役割 |
|------|------|
| **主張** | この段落が読者に受け入れさせたいこと。**原則1段落に1つ** |
| **根拠** | 主張を支持する。受け入れられたら捨ててよい |
| **定義** | 新規概念の導入。以降で使われるので捨てられない |
| **具体例** | 理解の補助。捨ててよい |
| **限定・留保** | 主張の適用範囲。捨ててよいが、無いと過大主張になる |

各根拠について「どの主張を支持するか」を辺として書く。
**どの主張も支持しない要素は削る。**

## Step 3: 順序を決める

原則は次の順。

1. **主張を先頭に置く**（トピックセンテンス）
2. 新規概念の定義（その段落で必要なもののみ）
3. 根拠を、強い順ではなく**依存順**に並べる
4. 限定・留保
5. 具体例（あれば）

これにより、主張を受け入れた読者は2以降を読み飛ばせる。
**これが「読む基準の明確さ」の実装である。**

## Step 4: 段落内の点検

- 新規概念を**3個以上導入していないか**。していれば段落を分割する
- 手順や列挙から始まっていないか。読者は覚えるべきか判断できない
- 前の段落で discharge したはずの概念を再び使っていないか
- 同じ概念を、全体で既に説明した表現と**違う言葉**で言い直していないか

## Step 5: 文の水準

順序が決まってから文を書く。

- 一文一義。主語と述語を対応させる
- 簡単な語で足りるときに難解な語を使わない
- 修飾語は自然な読み順に置く
- 否定形で説明しない。「Xではない」より「Yである」

## 出力

対象段落の**書き換え案**を提示する。あわせて次を短く報告する。

- この段落の主張（1文）
- 導入する概念と消費する概念
- 対応する評定要素
- 分割を推奨する場合はその理由

`worksheet/graph.md` の更新が必要な変更（概念の追加・削除、消費点の移動）が生じた場合は、
**本文を書き換える前に** `/doc-graph` に戻る。
