# Doc Constraints — 形式制約の採取

## 原則

- **一次資料から採る。** 様式ファイル、記入要領、投稿規定を発行元から直接取得する。
  解説サイト・過去の自分のファイル・先輩のファイルはすべて二次情報
- **原文を引用する。** 要約すると「この項目は(2)に含めてよいか」を後で判断できなくなる
- **採取元と採取日を記録する**

## 採取項目

| 項目 | 注意 |
|------|------|
| 記載項目とその順序 | `(1)(2)(3)…` の指定。**原文のまま引用** |
| 分量上限 | 頁数・字数・行数。**数え方に影響する要素**（削除必須の指示書き等）も記録 |
| 体裁 | フォントサイズ下限、色の可否、見出しの位置の制約 |
| 提出期限・形式 | |
| 役割の記載義務 | 共著者・分担者の役割を明記せよという指示があるか |

## よくある見落とし

- **提出時に削除する指示書き・留意事項が分量を占めている。** 分量を測るときは
  必ず外した状態で測る。テンプレート同梱の注意書きが1頁近くを占めることがある
- **モノクロ化される。** カラーで作った図が判読不能になる
- **項目のタイトルが頁の先頭に来ること**のような、レイアウトへの制約
- 空白頁を削除してはいけない、という指示

## PDFが読めないとき

テキスト抽出が文字化けする場合は、ページを画像に変換して読む。
**記憶や二次情報で代用しない。**

```sh
pdftotext -layout in.pdf out.txt     # まずこれ
pdftoppm -png -r 150 -f N -l N in.pdf out   # 化けたら画像で読む
```

## 出力

`worksheet/constraints.md` を更新する。更新したら `worksheet/graph.md` の直列化案が
まだ制約を満たしているかを必ず再点検する。
